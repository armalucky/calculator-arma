# Размещение LuckyMap

Сайт полностью статический. На сервер загружается содержимое `web/dist`; Node.js нужен только при сборке. Программа для Windows остаётся отдельной.

## Через GitHub и автоматическую сборку

1. Добавьте в репозиторий исходники проекта, включая `web/package-lock.json`, папки `web`, `data` и разрешённую обложку в `references/mod-luckygames`. Подготовка ресурсов требует весь репозиторий. Перед отправкой просмотрите список изменений; не добавляйте файлы через принудительный обход `.gitignore`.
2. Подключите этот GitHub-репозиторий к хостингу, который умеет собирать и раздавать статические сайты. Используйте Node.js 24, соответствующий проверенному окружению.
3. Если рабочая директория сборки — корень репозитория, задайте команду `npm --prefix web ci && npm --prefix web run check && npm --prefix web test && npm --prefix web run build`, а выходную папку — `web/dist`.
4. Если хостинг отдельно задаёт рабочую директорию `web`, команда — `npm ci && npm run check && npm test && npm run build`, выходная папка — `dist`. При этом соседние `data`, `references` и исходники, используемые проверкой эталона, должны оставаться доступны при сборке: нельзя загружать одну папку `web`.
5. Включите HTTPS и раздачу index.html для каталога сайта. Для подпапки используйте адрес с завершающим `/`, например `https://example.com/luckymap/`, и перенаправление с `/luckymap` на `/luckymap/`. JS, CSS, JSON и изображения должны отдаваться с соответствующими MIME-типами; отсутствующие ресурсы — с 404. У приложения нет маршрутизатора и необходимости подменять все 404 главной страницей.
6. После публикации выполните из `web`: `npm run verify:delivery -- https://example.com/luckymap/`. В браузере проверьте карту, выбор A/B, подбор позиции, сохранение после перезагрузки, скачивание и импорт JSON. Только после этого считайте размещение проверенным.

Конкретные поля панели и настройки домена будут уточнены при выборе хостинга. GitHub хранит исходники; сам факт загрузки файлов в репозиторий не запускает сайт.

## Загрузка готового архива

Архив `dist/web-release-*/luckymap-web.zip` создаётся после [приёмки](WEB-ACCEPTANCE.md). Распакуйте его содержимое в публичный каталог хостинга так, чтобы index.html лежал непосредственно в корне сайта или выбранной подпапки. Не загружайте весь проект в публичный каталог. Далее выполните пункты 5–6 выше. Пересобирать сайт на сервере в этом варианте не нужно.

При обновлении заменяйте сборку целиком, по возможности атомарно. Для index.html и resources/manifest.json используйте перепроверку кеша; файлы с хешами в именах допускают длительное кеширование. Не включайте Service Worker автоматически: управление офлайн-кешем в приложении не реализовано.

## Локальные данные

Перед переходом с локального адреса на публичный экспортируйте JSON, затем импортируйте его на сайте. Хранилище привязано к протоколу, домену и порту, а не к аккаунту GitHub. Подпапки одного origin используют общую базу LuckyMap; для независимых установок нужны разные origin. Очистка данных сайта удаляет сохранения, поэтому JSON остаётся способом резервного копирования и переноса между устройствами.
