# Шаг 5: перенос игровой логики

Дата: 2026-09-09. Эталон — существующая LuckyMap для Arma Reforger, зафиксированная в [DESKTOP-BASELINE.md](DESKTOP-BASELINE.md).

## Результат

Созданы независимые от интерфейса модули TypeScript:

- `web/domain/coordinates.ts` — проверка координат, ввод точных значений и клеток, центр крайней обрезанной клетки, формат клетки, расстояние.
- `web/domain/game-tables.ts` — проверка JSON, значения по умолчанию C#, существующие профили LuckyMap, расчёт, округление, исходные сообщения и сведения об источнике таблицы.
- `web/domain/roads.ts` — проверка исходных дорожных полигонов, расстояния и пространственный индекс той же структуры, что в C#.
- `web/domain/planning.ts` — параметры и пределы существующего подбора, оценка позиции, поиск ближайшей сценарной точки и массив ячеек области подбора.
- `web/features/resources/game-data.ts` — явные загрузчики проверенных таблиц и геометрии. Независимые запросы выполняются параллельно, поддерживается отмена. Импорт модулей не загружает ресурсы сам по себе.

Используются только существующие игровые данные. Базовые JSON не переписаны. M116 получает отдельные копии строк по существующему правилу LuckyUI; оригинальный профиль M107 при этом не меняется. Новые физические модели, поправки и профили не добавлены.

Маска представлена переносимым массивом 0/1 размером 512×512 с тем же порядком ячеек, что у настольного Bitmap. Цвет вынесен отдельной константой. Это позволяет подключить Canvas и Web Worker на следующих этапах без зависимости предметной логики от DOM.

## Как получен независимый эталон

`npm run reference:domain` запускает `web/scripts/Export-DomainReference.ps1`. Он компилирует неизменённые `app/MapApp.cs`, `app/GameTables.cs`, `app/PositionPlanner.cs` вместе с тестовым экспортёром в отдельную DLL внутри игнорируемой папки `web/work/`. Вызываются оригинальные методы C#; Windows-интерфейс не создаётся. Правило создания игровых M116-профилей взято из текущего LuckyUI.

Результаты записаны в `web/tests/fixtures/domain-reference.json`. Это тестовые синтетические случаи и текущие игровые ресурсы, без пользовательских сохранений. Файл содержит SHA-256 исходников и входных данных; тест прекращает проверку при их изменении и требует осознанно обновить эталон.

Генерация эталона требует Windows/.NET, обычный запуск `npm test` — только Node.js. При изменении тестового экспортёра эталон нужно пересоздать этой командой. Ожидаемые значения нельзя редактировать вручную для прохождения тестов.

## Проверенное соответствие

| Область | Объём | Сравнение |
|---|---:|---|
| Игровые профили | 31 | 11 миномётных, 10 M107, 10 M116 |
| Расчёты | 2408 | Все исходные строки и промежутки, пределы и допуски диапазона, направления, пустые/совпавшие/некорректные точки |
| Ввод координат | 42 | Точные координаты, клетки, край карты, разделители, дроби, экспоненты, ошибки и сообщения |
| Расстояния до дорог | 166 | Исходные 9426 полигонов и отдельная контрольная геометрия |
| Оценки позиции | 388 | Разные профили/фильтры, точки внутри/вне условий и пограничные значения |
| Области подбора | 8 | SHA-256 всех 2 097 152 ячеек, количество подходящих ячеек и ориентация массива |
| Округление | 9 | Прямое сравнение с Math.Round в выбранном режиме C# |

Целые единицы, единицы шкалы, границы использованных строк, флаги и сообщения сравниваются точно. Для непрерывных чисел до сравнения задан допуск `1e-9 + abs(expected) × 1e-12`, учитывающий различия вычислительных библиотек и JSON-представления double. Допуски не подбирались под обнаруженные расхождения. Маски совпали полностью, без допуска.

Дополнительные проверки проверяют повреждённые таблицы, дубликаты ID, числовые пределы, независимость M116-копий, совпадение пространственного индекса с полным перебором, вырожденную геометрию, фильтры с нулевыми отступами, углы ячеек, явную загрузку данных и ошибки ресурсов.

- Все 274 файла контрольного списка Windows остались неизменными; `git diff --check` без ошибок.

## Границы этапа

Вычислительное ядро пока не подключено к элементам управления страницы и не загружается стартовым экраном. Полноценные панели, карта, управление несколькими орудиями, совместимость сохранений и миграция имён при импорте выполняются на соответствующих следующих этапах. Сравнение результатов в Node.js не заменяет будущие сквозные проверки браузерного интерфейса или проверку в игре.

Пункты матрицы CALC/PLAN не объявляются полностью принятыми до подключения интерфейса. Реализована и проверена их вычислительная часть. Следующий шаг — интерактивная карта: Canvas, масштабирование, перемещение, слои и маркеры на подготовленных ресурсах.
