# Этап 7 — игровой интерфейс LuckyMap

Дата: 09.09.2026. Веб-версия остаётся самостоятельным статическим приложением. Desktop-исходники, сборки и сохранения не изменены.

## Реализовано

| Область матрицы | Поведение |
|---|---|
| GUN-01–05 | 1–6 орудий, независимые координаты/профили/фильтры, копирование цели при добавлении, однократное назначение цели всем, подтверждение удаления, стабильные номера |
| CALC-01–06 | Все 31 существующий профиль, отдельный выбор 82 мм/M777, селекторы снаряда/заряда/траектории, азимут/возвышение/время, источник и диапазон; понятные причины отсутствия решения |
| PLAN-01–06 | Вкладка подбора, три фильтра с прежними пределами и значениями по умолчанию, маска и оценка A, показ вокруг B, обновление без блокировки карты и без устаревшего ответа |
| POINT-01–04 | Исходные точки и общие закладки с клетками, назначение A/B по режиму, переименование; оригинальные данные фильтра не меняются |
| MAP-09, COORD-04 | Маркеры всех заданных орудий, активная цель и линия; сброс только активных A/B и их результатов |
| UI | Обложка LuckyGames, палитра, панели расчётов/подбора, RU/EN, прокрутка панелей, справка/F1, полный экран и обработка отказа API |

Неприменённый ввод координат не меняет точку, сохраняется при переключении языка и орудий. Значения фильтров применяются кнопкой или Enter; неверные значения оставляют предыдущие параметры и результат. Подсказка к выбору точки объясняет: A назначается в режиме позиции, иначе B.

Расчёт использует только перенесённые игровые таблицы; новые физические модели не добавлялись. Ограничения исходного метода доступны рядом с результатами. Профили без исходных данных отсутствуют в селекторах.

## Реализация

`features/fleet/state.ts` хранит нормализованную сессию в памяти. Общее состояние названий и закладок отделено от данных каждого орудия. Это пока не настольный формат файла; преобразование и строгая проверка импорта выполняются на этапе 8.

`features/planning/planning.worker.ts` исполняет исходную перенесённую логику планирования вне главного потока. Каждый набор входных данных имеет ключ. При изменении данных предыдущий worker завершается, старая маска немедленно скрывается; запоздалый ответ не может стать текущим. При отказе worker есть повтор. Слои и переименования не влияют на исходные сценарные исключения.

В production-сборку входит отдельный файл worker. При размещении нужно публиковать всю папку `web/dist`, включая `assets`, а не только index.html.

## Проверки

- `npm run check`: TypeScript и lint проходят.
- `npm test`: 28 групп проходят. Новые тесты проверяют независимость орудий, лимит, номера, общие цели/закладки, доступность каждого профиля и форматирование.
- Production-worker проверен через Node-мост: полный хеш и число ячеек маски совпадают с C#; отключение слоя сохраняет оценку; повреждённая геометрия даёт ошибку.
- Существующие проверки 2408 расчётов, 166 дорожных расстояний, 388 оценок и восьми полных масок проходят.
- `npm run build`: успешная production-сборка, worker вынесен отдельным ресурсом.

В Headless Chrome 152 проверены пользовательские действия: ввод A/B; значения 90.0°, 85.1°, 33.0 с для контрольного профиля he4 на игровой дистанции 400 м; добавление/переключение орудий; независимость профилей; копирование общей цели без последующей связи; отмена и подтверждение удаления; повторное использование номера; ограничение шестью; закладка и общее переименование; смена языка с неприменённым текстом; ошибка фильтров; невозможный запас; быстрые изменения с подавлением старой маски; сброс результатов; справка с Escape и возвратом фокуса; вход в полный экран.

Компоновка просмотрена при 1440×960, 1180×820 и эмуляции 944×656 CSS-пикселей с DPR 1.25. Для небольшой высоты доступны отдельные прокручиваемые панели. Эмуляция DPR не заменяет будущую проверку нативного масштаба браузера 125%. Скриншоты находятся в игнорируемой папке `web/work/step7-*.png`. Полная приёмка в Edge/Firefox и сквозная проверка после хранения ещё впереди.
