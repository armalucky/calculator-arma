# Этап 8 — сохранение веб-сессии

Дата: 09.09.2026. Реализованы SAVE-01–12 и миграция сценарных названий POINT-05 из матрицы; окончательная приёмка во всех целевых браузерах выполняется следующим этапом.

## Пользовательское поведение

- Принятые изменения сессии автоматически записываются в браузер. Статус «Сохранено» появляется после завершения транзакции, а не после запуска запроса. При быстрых изменениях очередь записывает последнюю принятую версию.
- «Сохранить все орудия» и Ctrl+S повторяют локальное сохранение. Неприменённый ввод координат и фильтров не становится частью сессии.
- «Экспорт JSON» скачивает `lucky-session.json`, совместимый с настольным FleetState версии 1. Все общие названия и закладки продублированы в Data каждого орудия, как в desktop-сохранении.
- Импорт принимает FleetState или классический Session версии 1. До чтения проверяется размер файла, затем весь JSON: версия, структура, номера/активное орудие, координаты, игровые профили, фильтры, имена и закладки. Предел — 2 000 000 байт и 1000 закладок. Неизвестные поля и расходящиеся общие данные отвергаются с пояснением.
- Перед заменой показываются файл, число орудий/закладок, активный номер, профили и точки. Отмена ничего не меняет. Замена вступает в силу только после успешной транзакции с резервированием предыдущей версии.
- При ошибке записи работа продолжается в памяти, статус предлагает экспорт. Кнопка повтора сохраняет накопленные изменения после восстановления доступа.
- При конфликте вкладок запись устаревшей вкладки приостанавливается. Локальные изменения доступны для экспорта; загрузка актуальной версии требует явного подтверждения.
- Повреждённая или неизвестная версия записи не заменяется новой автоматически. Доступны скачивание исходных данных, восстановление валидной резервной копии и подтверждённое создание новой сессии.

## Хранилище и миграции

IndexedDB: база `luckymap.web.sessions`, физическая версия 1, object store `records`.

| Ключ | Содержимое |
|---|---|
| `current` | `{schema: 1, revision: UUID, savedAt: ISO, session: FleetState}` |
| `previous` | Предыдущая корректная запись; меняется атомарно вместе с current |
| `recovery` | Исходная повреждённая/неизвестная запись после явного восстановления или сброса |

Сравнение текущей записи с прочитанной базовой версией и замена выполняются внутри одной readwrite-транзакции. Это защищает от перезаписи даже при недоступном BroadcastChannel. Канал ускоряет уведомление других вкладок; при фокусе также проверяется актуальность.

Версия веб-конверта независима от desktop Version=1. Для проверки пути миграции поддержан технический вход `{schema: 0, revision, payload: FleetState}`: он преобразуется в schema=1 через тот же атомарный путь с сохранением исходного конверта. Это тестовый предшествующий формат, ранее опубликованной веб-базы не было. Неизвестная версия блокирует автозапись. При отказе миграции исходная запись остаётся на месте.

Классические отсутствующие профили получают те же значения по умолчанию, что desktop: he4 и m777-2-low. При NamingVersion < 2 имена исходных сценарных точек заменяются текущими исходными именами, точно как SiteNames.ApplyScenarioNames. Экспорт устанавливает NamingVersion=2, поэтому последующие пользовательские переименования сохраняются.

Настройки отображения отделены от настольного JSON: localStorage `luckymap.web.preferences.v1` содержит язык, слои и камеру. Некорректные отдельные значения заменяются допустимыми, сессия при этом не меняется. Настройки записываются с короткой задержкой и дополнительно при уходе со страницы; сохранение сессии не зависит от закрытия страницы.

Хранилище привязано к origin и профилю браузера. Смена домена/порта, другое устройство и очистка данных сайта не переносят сохранение. Экспорт служит переносимой копией. Аккаунтов, облачной синхронизации и загрузки пользовательского JSON на сервер нет.

## Проверки

`npm test`: 38 групп. Десять новых проверяют весь цикл JSON, классическую миграцию имён, ошибки структуры/версий/размера/профилей, независимые настройки, очередь записи, отказ квоты, конфликт, восстановление, резервирование при замене/миграции и недоступный IndexedDB при старте.

`npm run verify:storage-desktop`: сгенерирована сессия шести орудий с независимыми точками, параметрами и общей закладкой. Исходный C# FleetState.Load принимает веб-экспорт; результат FleetState.Save повторно читается веб-кодеком с равенством всех данных. Отдельно совпадает миграция классического Session через исходный SiteNames.ApplyScenarioNames. Окна desktop-приложения не запускаются; временная DLL и файлы лежат в web/work.

`npm run verify:storage-browser`: настоящий Headless Chrome с отдельным временным профилем. Проверены восстановление после перезагрузки, исключение неприменённого текста, язык/слои/камера, фактическое скачивание JSON на диск, файловый импорт с отменой/подтверждением и резервной копией, повреждённый файл, конфликт двух вкладок, отказ put в IndexedDB с последующим повтором, повреждение primary и восстановление backup с сохранением первичной записи в recovery. Скачанный JSON побайтно разбирается и сравнивается с сохранённым payload. Для этих проверок используется CDP, поскольку скачивание через установленный agent-browser давало сбой также на независимом тестовом файле.

`npm run check` и production-сборка проходят. Файлы ПК-программы и пользовательские сохранения проверяются по 274 SHA-256 базовой копии и не изменяются. Синтетические данные, профили браузера и скриншоты находятся только в игнорируемой web/work.

Следующий этап — сквозная приёмка, целевые браузеры и проверка готовности статической сборки к размещению из GitHub. Публикация ещё не выполнена.
