# LuckyMap: функции и приёмка веб-версии

Шаг 2 плана переноса. Дата: 2026-09-09.
Эталон: LuckyMap из коммита `1f89ee5ab5a8821262b04f9d9bd25605e9ab27bb`; результаты проверки Windows — [DESKTOP-BASELINE.md](DESKTOP-BASELINE.md).

Документ описывает требования первого выпуска. Прогресс реализации: [ядро — этап 5](WEB-DOMAIN.md), [карта — этап 6](WEB-MAP.md), [интерфейс — этап 7](WEB-INTERFACE.md), [сохранение — этап 8](WEB-STORAGE.md). [Сквозная приёмка — этап 9](WEB-ACCEPTANCE.md) завершена в Chrome и Edge; ограничения проверки указаны в отчёте. Публикация ещё впереди. Основной сценарий — использование игровой карты Arma Reforger в браузере на ПК. Windows-версии остаются самостоятельными.

## Обозначения

- **Перенос** — сохранить наблюдаемое поведение LuckyMap.
- **Адаптация** — сохранить назначение функции с учётом браузера.
- **Добавление** — необходимая возможность веб-версии, которой сейчас нет в настольном интерфейсе.

Каждая строка обязательна для первой полной веб-версии. При реализации к ID добавляются ссылки на проверки и результат. Наличие старого Windows-теста само по себе не подтверждает готовность веб-функции.

| CALC-04 | Перенос | Отсутствие A/B, совпавшие точки, отсутствие таблицы и выход за её пределы дают понятное сообщение; предыдущий успешный результат не остаётся как актуальный. |
| CALC-05 | Перенос | Источник, диапазон и пояснения метода доступны рядом с результатом или в подсказке. Числовое округление и форматирование совпадают с эталоном, включая граничные случаи. |
| CALC-06 | Перенос | Сохраняются пояснения об игровом назначении и ограничениях текущих таблиц. Не добавляются новые физические модели или недостающие данные. |

## Точки и закладки

| ID | Тип | Функция и критерий приёмки |
|---|---|---|

| POINT-04 | Перенос | «Закладка» добавляет A в режиме позиции, иначе B. Без точки выводится сообщение; без имени используется имя по клетке. Закладки общие для всех орудий. |
| POINT-05 | Перенос | При импорте старой сессии применяется существующая миграция сценарных названий; последующие пользовательские переименования сохраняются. |

Удаления закладок в текущем интерфейсе нет: его не считать утраченной функцией и не включать как обязательное расширение этого переноса.

## Сохранение в браузере и перенос файлов

Пользователь согласовал автосохранение в браузере и импорт/экспорт JSON. Это обязательная часть веб-версии.

| ID | Тип | Функция и критерий приёмки |
|---|---|---|
| SAVE-01 | Добавление | IndexedDB хранит принятую сессию: все орудия, активный номер, точки, профили, параметры подбора, общие названия и закладки. После завершённого сохранения перезагрузка восстанавливает те же данные. |
| SAVE-02 | Добавление | Автосохранение после принятых изменений, без ожидания закрытия вкладки. Видны состояния «Сохранение», «Сохранено» и ошибка; успешный статус появляется только после завершения транзакции. |
| SAVE-03 | Адаптация | «Сохранить все орудия» и Ctrl+S принудительно сохраняют в браузер. Подпись/подсказка отличает это действие от скачивания JSON. |
| SAVE-04 | Добавление | Экспорт скачивает JSON, совместимый с LuckyMap `FleetState.Version=1`; импорт такого файла в чистую веб-сессию восстанавливает данные. Файл также проверяется настольным загрузчиком в изолированной копии. |
| SAVE-05 | Адаптация | Импорт существующего `lucky-session.json` и классического `session.json` через выбор файла; классическая сессия становится первым орудием. Нет автоматического чтения папки `user-data`. |
| SAVE-06 | Добавление | До замены сессии импорт полностью проверяется; показываются краткие сведения и подтверждение замены. Отмена и ошибка сохраняют текущие данные; до успешной замены хранится предыдущая корректная версия. |
| SAVE-07 | Перенос | Проверяются версия, размер файла до 2 000 000 байт, структура, уникальность номеров, активное орудие, координаты, профили, фильтры и лимит закладок. Несовместимый файл получает понятную ошибку, а не молчаливую потерю полей. |
| SAVE-08 | Адаптация | Повреждённое хранилище не затирается пустой сессией автоматически. Доступен путь восстановления/явного сброса и экспорт читаемых данных; ошибочное состояние не объявляется сохранённым. |
| SAVE-09 | Добавление | При отказе записи/нехватке места работа продолжается в памяти с заметным сообщением и доступным экспортом. Кеш карты не используется как хранилище пользовательской сессии. |
| SAVE-10 | Добавление | Обновление схемы хранилища сохраняет старые данные до успешной миграции. Обычное обновление сайта проверяется на сохранённой сессии; номера версий веб-хранилища и настольного JSON независимы. |
| SAVE-11 | Добавление | Две вкладки не перезаписывают незаметно разные версии сессии: при конфликте устаревшая вкладка приостанавливает запись и предлагает загрузить актуальную версию либо экспортировать свою. |
| SAVE-12 | Адаптация | Язык и настройки отображения сохраняются отдельно от совместимого настольного JSON. Проверяется восстановление языка, слоёв и вида карты; неверные настройки заменяются допустимыми значениями без удаления сессии. |

### Границы данных

| Категория | Что входит | Правило |
|---|---|---|
| Состояние одного орудия | A/B, тип оружия, отдельные выбранные профили, параметры подбора | Независимо для каждого номера |
| Общие данные сессии | Список орудий, активный номер, имена, закладки, версия миграции названий | Один согласованный набор; при экспорте воспроизводится структура существующего FleetState |
| Настройки веб-интерфейса | Язык, видимость слоёв, центр и масштаб карты | Отдельно от настольного файла, с проверкой значений |
| Временный ввод | Ещё не применённый текст полей | Не превращать в A/B при автосохранении; сохранять при переключении языка |
| Ресурсы приложения | Подложка, тайлы, таблицы, геометрия | Общие статические ресурсы, отдельно от пользовательских данных |

Текущий настольный Session не содержит центра/масштаба карты и переключателей слоёв. Их сохранение в веб-интерфейсе — добавление, а не существующая совместимость файла.

IndexedDB привязан к origin (протокол, хост и порт) и профилю браузера. Для нескольких приложений на одном origin нужны разные имена баз. Смена домена не переносит данные автоматически; разные устройства не синхронизируются. Очистка данных сайта и политика освобождения места могут удалить локальные данные, поэтому экспорт обязателен. Источники: [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API/Basic_Terminology), [хранение и удаление данных](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria).

## Проверка соответствия

Проверки числовых результатов выполняются на синтетических игровых сессиях. Реальные пользовательские сохранения не становятся тестовыми файлами и не попадают в GitHub.

| Область | Существующая основа | Проверка веб-версии |
|---|---|---|
| Орудия и базовый интерфейс | `tests/Verify-Lucky.ps1` | Сценарии добавления, переключения, назначения цели, сброса, удаления и восстановления |
| Таблицы и профили | `tests/Verify-GameTables.ps1`, `Verify-M777.ps1`, `Verify-Smoke.ps1` | Сравнение с результатами C# на всех профилях, границах и неверном вводе |
| Геометрия и карта | `tests/Verify-VectorMap.ps1`, `Verify-Buildings.ps1`, `Verify-MapDetail.ps1` | Координатные контрольные точки, слои, масштабирование, тайлы и изменение окна |
| Подбор | `tests/Verify-Planning.ps1` | Сравнение результатов и области, смена входных данных, отсутствие устаревших результатов |
| Язык и окно | `tests/Verify-Language.ps1`, `Verify-WindowMode.ps1` | Соответствие текстов и поведения с указанными браузерными адаптациями |
| Хранение | Схемы в `Fleet.cs` и `MapApp.cs` | Перезагрузка, импорт/экспорт, отмена, повреждение, отказ записи, миграции, конфликт вкладок |
| Сборка | `tools/Package-Release.ps1`, `tests/Verify-Portable.ps1` | Windows-проверки отдельно; веб-сборка из чистой копии и загрузка опубликованных ресурсов |

Минимальный сквозной сценарий: открыть чистую сессию → задать точки → добавить несколько орудий с разными профилями → назначить общую цель → независимо изменить одну → добавить/переименовать закладку → переключить слои и язык → дождаться сохранения → перезагрузить → экспортировать → импортировать в чистую сессию → сравнить данные и результаты. Затем отдельно проверить удаление, отмену импорта и отказ хранения.

Приёмка в Chrome, Edge и Firefox на ПК: зафиксировать фактические версии браузеров, размер окна и результаты. Сверять отображаемые числовые значения с Windows точно; допуск для неокруглённых значений обосновать при переносе, до оценки результатов теста. Для карты проверять координаты и визуальную совмещённость, не требовать попиксельного совпадения разных систем отрисовки.

## Границы первого выпуска

Включены все строки этого документа, автономная статическая веб-сборка, подготовка к размещению из GitHub, инструкция запуска и сохранение работоспособности Windows. Публикация проверяется на последующих шагах, а не считается выполненной этим документом.

Не входят: аккаунты, облачная синхронизация, совместная сессия нескольких пользователей, новые карты/профили, новые физические модели, гарантированный запуск сайта без сети, установка PWA, специальный мобильный интерфейс и удаление закладок. Эти возможности не нужны для соответствия существующей ПК-программе. Уменьшение окна браузера поддерживается; полная проверка сенсорного управления может быть отдельным этапом.

Текущий следующий шаг: подключить GitHub и хостинг по [инструкции размещения](WEB-HOSTING.md), проверить публичный адрес. Локальная приёмка Chrome/Edge выполнена; проверка Firefox остаётся открытой, поскольку он не установлен в окружении.
