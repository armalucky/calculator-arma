# Шаг 4: общие ресурсы для веб-версии

Дата: 2026-09-09. Этот этап подготавливает данные; перенос логики и отрисовка карты выполняются дальше.

## Подготовка

`web/scripts/prepare-resources.mjs` использует явный список исходников, а не рекурсивное копирование репозитория. Он автоматически запускается перед `npm run dev` и `npm run build`; отдельно — `npm run prepare:resources` из web.

| Источник | Количество | Назначение |
|---|---:|---|
| `data/game-tables.json`, `data/m777-tables.json` | 2 | Исходные игровые таблицы без преобразований |
| `data/maps/bakhmut/desktop-background.jpg` | 1 | Обзорная подложка |
| `data/maps/bakhmut/detail/background/*.png` | 100 | Исходные тайлы детализации с рамкой |
| `roads.json`, `buildings.json`, `points.json` в папке карты | 3 | Векторная геометрия и сценарные точки |
| Обложка `references/mod-luckygames/scenario0_1024x512.jpg` | 1 | Существующий ресурс оформления |
| `LICENSE`, `LICENSE.ru.md` | 2 | Тексты лицензии |

Итого 109 ресурсов, 50,80 МиБ, плюс каталог 27 557 байт. Исходные bytes сохраняются полностью, включая поля источников и исходные названия. Таблицы M116 не создаются на этом шаге: их существующее поведение будет перенесено вместе с игровой логикой.

Сборка не включает пользовательские сохранения, EXE, архивы модов, исследовательские материалы, полный исходный фон, дублирующие растровые дороги и неиспользуемые данные высот.

## Формат и обновления

Генератор создаёт `web/public/resources/manifest.json` и файлы вида `<sha256>.<extension>`. В каталоге каждому исходному логическому пути сопоставлены имя подготовленного файла, размер и SHA-256. Каталог также фиксирует границы карты 10240 м, сетку 10×10 тайлов и рамку 1 пиксель. Никакие координаты и изображения не пересчитываются.

Перед записью проверяются наличие и непустое содержимое всего списка, структуры JSON, числовые координаты/строки, заголовки JPEG и размеры PNG. Это проверка подготовки ресурсов; полная предметная валидация игровых профилей остаётся задачей переноса логики. Каталог заменяется после успешной записи ресурсов. Устаревшие сгенерированные файлы удаляются только из собственной папки и только после проверки допустимых имён. Неизвестные файлы или ссылки в выходной папке останавливают подготовку.

`public/resources/` и `dist/` исключены из Git. Чтобы изменить данные, обновляют общие исходники, затем пересобирают web. Не редактировать сгенерированные копии. Для хостинга загружается результат `web/dist`; сборке из GitHub нужен весь репозиторий с исходными ресурсами.

## Загрузка

`features/resources/catalog.ts` проверяет каталог и строит URL относительно адреса сайта, включая подпапку. На старте страницы запрашивается только каталог с `cache: no-cache` для перепроверки актуальности. Подложка, геометрия, таблицы и тайлы загружаются отдельно по мере потребности. Модуль возвращает JSON как unknown до предметной проверки, поддерживает AbortSignal, не скрывает HTTP-ошибки.

Хеши в именах позволяют менять ресурс без сохранения прежнего URL. Постоянный офлайн-кеш не добавлен. Настройку долговременного кеширования файлов с хешами и перепроверки каталога нужно сохранить при настройке реального хостинга. Вкладка со старым каталогом после обновления сайта при недоступном старом ресурсе должна предложить обновление, а не подставить неверные данные; эта обработка понадобится при интеграции карты.

Стартовая страница показывает загрузку каталога, успех или ошибку с предложением перезагрузить страницу. Карта, вычисления и пользовательские сохранения по-прежнему недоступны.
