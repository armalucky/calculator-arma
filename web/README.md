# LuckyMap Web — этап 8

Самостоятельный клиентский проект: React + TypeScript + Vite. Работают карта RU/EN, до шести независимых орудий, все 31 игровой профиль, панель результатов и подбор позиции в Web Worker. Доступны общие закладки, переименование, справка и полный экран. Сессия автоматически сохраняется в IndexedDB и восстанавливается после перезагрузки; предусмотрены импорт/экспорт JSON, резервная копия и защита от конфликта вкладок. Windows-программы собираются прежними командами независимо от web.

## Запуск

Требуется Node.js, удовлетворяющий `engines` в package.json, и npm. Проверено на Node.js 24.13.1 / npm 11.8.0. Из корня репозитория:

```powershell
cd web
npm ci
npm run dev
```

Если PowerShell запрещает `npm.ps1`, используйте `npm.cmd`. Адрес: http://127.0.0.1:5173. Если порт занят, сервер завершится с ошибкой; явно выбрать другой можно командой `npm run dev -- --port 5174`. Остановка — Ctrl+C.

## Проверки и сборка

Из папки web:

```powershell
npm run check
npm test
npm run build
npm run preview
```

`check` проверяет типы и lint. `build` также проверяет типы и создаёт `web/dist/`. `preview` раздаёт готовую сборку на http://127.0.0.1:4173. Это статический сайт: сервер Node.js на хостинге не нужен. Посетителю нужен браузер с JavaScript. Открытие `index.html` через `file://` не является способом запуска.

Перед `dev` и `build` автоматически выполняется `prepare:resources`: скрипт выбирает 109 файлов из общих ресурсов репозитория, проверяет структуру данных и создаёт `public/resources/`. Исходники не меняются. Для сборки нужен весь репозиторий, а не одна папка web. В Git сохраняются исходные данные и скрипт; сгенерированные копии исключены.

`npm test` проверяет побайтовое соответствие всех ресурсов, состав каталога, ошибки и ленивую загрузку. При работающем preview команда `npm run verify:delivery` проверяет HTTP и SHA-256 всех ресурсов. Для другого адреса: `npm run verify:delivery -- https://example.com/luckymap/` (обязателен конечный `/`).

Также `npm test` сравнивает TypeScript с сохранёнными результатами C#: 2408 расчётов для 31 профиля, 42 случая ввода координат, 166 дорожных расстояний, 388 оценок позиции и 8 полных масок. Тесты запускаются на Node.js без .NET. Для намеренного обновления эталона на Windows: `npm run reference:domain`. Эта отдельная команда компилирует текущие классические исходники во временную DLL внутри `web/work/`, не запускает окна и не меняет EXE или сохранения. Файл `tests/fixtures/domain-reference.json` хранится в Git; хеши исходников и данных в нём предотвращают незаметное устаревание эталона. Подробности и допуски: [WEB-DOMAIN.md](../docs/WEB-DOMAIN.md).

Пути сборки относительные (`base: './'`) для размещения в подпапке. Будущие публичные ресурсы адресовать через `import.meta.env.BASE_URL`, без корневых `/data/...` путей. Пока приложение имеет одну страницу без маршрутизатора.

## Структура

| Путь | Назначение |
|---|---|
| `index.html`, `app/main.tsx` | Браузерная точка входа |
| `app/page.tsx`, `app/globals.css` | Стартовая страница и палитра LuckyMap |
| `domain/` | Чистые модули координат, игровых таблиц, дорожного индекса и подбора позиции |
| `features/map/` | Canvas-карта и управление |
| `features/fleet/` | Орудия и общие точки |
| `features/calculation/`, `features/planning/` | Панели результатов и подбора |
| `features/storage/` | IndexedDB и JSON-совместимость |
| `features/i18n/` | Типизированные тексты RU/EN |
| `features/resources/` | Каталог, адресация ресурсов и типизированные загрузчики таблиц/геометрии |
| `scripts/`, `tests/` | Подготовка ресурсов, проверка доставки и тесты |
| `components/ui/`, `lib/` | Базовая кнопка shadcn и утилита классов; остальные компоненты добавляются при необходимости |
| `public/resources/` | Автоматически подготовленные публичные ресурсы и каталог |
| `vite.config.ts`, `tsconfig.json` | Сборка и строгая проверка TypeScript |

База создана официальным `@openai/create-sites@0.3.0` с shadcn и адаптирована к согласованному клиентскому Vite-проекту: серверные Vinext/Cloudflare зависимости удалены. `.openai/hosting.json` указывает статическую папку; сайт не зарегистрирован и не опубликован. Наличие компонентов шаблона не означает добавление соответствующих функций в продукт.

Версии закреплены в `package-lock.json`; повторная установка — `npm ci`. `node_modules`, `dist` и `public/resources` исключены из Git. Прямой доступ к корневым папкам через веб-сервер закрыт; публикуются только копии из явного списка в `scripts/prepare-resources.mjs`. Пользовательские сохранения, EXE, архивы модов и исследовательские файлы в этот список не входят.

На старте загружаются каталог около 27 КБ, геометрия дорог/зданий, точки сценария, игровые таблицы, обзорная подложка и обложка. При приближении запрашиваются видимые тайлы: до четырёх запросов одновременно, до 24 декодированных изображений в кеше. Имена файлов содержат SHA-256, каталог запрашивается с перепроверкой кеша. Пользовательские сессии хранятся отдельно от ресурсов. Service Worker и гарантированный офлайн-режим не реализованы. Подробности: [карта и проверки](../docs/WEB-MAP.md), [подготовка ресурсов](../docs/WEB-RESOURCES.md).

## Сохранение и перенос

Следите за статусом над вкладками орудий. «Сохранить все орудия» / Ctrl+S повторяет локальное сохранение; «Экспорт JSON» скачивает совместимый `lucky-session.json`. Импорт принимает этот файл или классический `session.json`, показывает состав и запрашивает подтверждение замены. Автоматического чтения `user-data` нет.

Данные привязаны к origin и профилю браузера: другой порт, домен или устройство имеет отдельное хранилище. Для переноса используйте JSON. При конфликте вкладок запись приостанавливается; можно выгрузить свою версию или явно загрузить актуальную. При повреждении доступны выгрузка исходных данных, восстановление резервной копии и явный сброс.

Дополнительные проверки из web:

```powershell
npm run verify:storage-desktop
# При работающем preview; используется отдельный временный профиль Chrome:
npm run verify:storage-browser
```

Первая команда требует Windows/.NET Framework и компилирует исходный C#-загрузчик в `web/work`. Вторая требует локальный Chrome (другой путь задаётся через `CHROME_PATH`) и проверяет реальные IndexedDB, скачивание/импорт, две вкладки и ошибки записи. Обе используют только синтетические данные. Пользовательские EXE, файлы сохранения и основной браузер не изменяются.
