# Предметная логика

Здесь находятся чистые TypeScript-модули, перенесённые на шаге 5 из текущей игровой ПК-версии. Они не импортируют React, DOM, файловую систему или IndexedDB. Импорт модулей не запускает запросы.

| Модуль | API |
|---|---|
| `coordinates.ts` | `validPoint`, `parseCoordinates`, `grid`, `distance`; игровые точки X/Z |
| `game-tables.ts` | `parseGameTables`, `createLuckyTables`, `calculate`; 31 существующий игровой профиль |
| `roads.ts` | `roadShape`, `RoadIndex`, `parseRoadIndex`; расстояние до края исходных дорожных полигонов |
| `planning.ts` | `parseSites`, `defaultPlanningOptions`, `assessPosition`, `createCandidateMask` |

Имена полей результатов/настроек сохранены близкими к C# для проверяемого соответствия. `Reason` у результата — дополнительный стабильный код для будущей локализации; `Message` пока содержит исходное русское сообщение. UI должен переводить по коду, не менять числовой результат.

`calculate` принимает таблицу из проверенного набора и точки либо null. Ошибочные/отсутствующие точки и выход за диапазон возвращают `Available: false`; прежнее решение не используется. Повреждённые ресурсы отклоняются на границе парсинга.

Маска возвращается как `Uint8Array` из 512×512 нулей/единиц, строки от северо-запада. Цвет для будущей отрисовки задан в `MASK_RGBA`. Это данные, а не Bitmap/Canvas; массив можно передать из Web Worker. При переносе интерфейса тяжёлый вызов следует запускать в Worker, а устаревшие задания отменять или игнорировать. Дорожный индекс строить внутри выполняющего вычисление контекста: его методы не переносятся через structuredClone.

Проверки: `npm test`, отчёт `docs/WEB-DOMAIN.md` в корне репозитория. Тестовые эталоны создаются оригинальной C#-логикой, не её копией в тестах TypeScript.

Совместимость настольного JSON реализуется преобразованием на границе хранения.
